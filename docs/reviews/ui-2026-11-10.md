# UI and visual design review

Date: 2026-11-10. Commit: 19b8dae. Lens: visual design only. Flows and missing features belong to the separate UX (user experience) review.

Basis:

- Source read: `ui/src/app.css`, `ui/src/App.svelte`, every file in `ui/src/views` and `ui/src/components`, `docs/design.md` sections 3, 5, and 6, and `docs/ux-review.md`.
- Screenshots: all 38 PNG files in `shots-drive`, `shots-board`, and `shots-notes` (Windows 10, light scheme, about 1216 by 839 pixels). The `shots-board` set predates commits 69b6b55 and fd2b514; where that matters, the item says so.
- Not seen in any screenshot: the dark scheme, the Guides poster grid, the Lightbox, the Album, and the cover crop box. Items about them come from the code and say "not seen".
- Contrast ratios are computed from the token values with the WCAG (Web Content Accessibility Guidelines) formula.
- Effort: S is under half a day, M is one to three days, L is a week or more.
- New token names such as `--accent-soft` are defined in the section "System".

## Verdict

1. The shell, the color tokens, and the board metaphors are sound. Serif section headings, figures, pastel notes, and polaroid images already look deliberate.
2. The app still reads as a web page, not a finished desktop app: underlined links everywhere, selection at 1.1:1 contrast, CodeMirror's default look, and flat gray controls.
3. The faults the owner will see first: entry and board names cut off beside empty space, rotated and clipped edge labels, and a selected string that turns into a purple bar.
4. The CSS (Cascading Style Sheets) has tokens but no stated scales: about 20 font sizes, 6 shadows, 6 icon sizes, 119 spacing declarations in raw pixels, and board colors outside `app.css`.
5. State the system once (section "System"), then make the top ten. Seven of the ten are S or S to M effort.

## Succeeding

Keep these.

- **Three-column shell.** A gray sidebar and a gray panel around a white content column, one top bar, and 28-pixel rails when folded. The structure reads at a glance on every screen (1-guide.png, 2-oak-new.png, b3-one-card.png).
- **Token base.** Each color is one `light-dark()` token (`app.css` 27-59). Density is a set of custom properties (`app.css` 3-18, 65-80). One rule removes all animation (`app.css` 92-97). One global focus ring (`app.css` 103-106). This needs stated scales, not a rewrite.
- **Encyclopedia headings and figures.** Serif section headings with a rule that stops at a float, and a bordered figure with a muted caption, read like Wikipedia (4-read.png; `app.css` 424-450, 591-638).
- **Alerts.** A colored bar and a small-caps title, with no quote mark (3-edit.png; `app.css` 534-587). Keep the form; fix one color and add icons (Failing 22).
- **Restrained tag color.** A tag's color is a dot on a neutral chip, not a colored fill (`app.css` 272-279; `TagPicker.svelte` 146-152). Lists stay calm, as in Linear.
- **Relation stage chips.** Outlined chips with square corners keep a staged verb distinct from a filled tag pill (`app.css` 265-270).
- **One suggestion list.** The relation line and the tag input share `Suggestions.svelte`, so both drop-downs look the same.
- **Palette.** Grouped rows, small-caps group titles, the tag path right-aligned and muted, a light backdrop, and a soft shadow (10-palette.png; `Palette.svelte` 249-327).
- **Notes.** Five soft pastels with page-colored text. A serif heading with a rule inside a note looks intended (n1-note.png, n3-green.png; `app.css` 51-55).
- **Polaroid images.** A white frame with a deeper bottom band and a light shadow reads as a photograph on dots, grid, and cork (n11-reopened.png; `BoardCanvas.svelte` 1142-1156).
- **Handles.** Eight square handles on notes and four on images, the same size at any zoom, as in Lucidchart (n1-note.png, img-1.png; `BoardCanvas.svelte` 1233-1241).
- **Color swatches.** Round swatches with a ring on the chosen one, for note and string colors (n1-note.png, n5-string.png; `BoardPanel.svelte` 408-419).
- **Dots and grid backgrounds.** Quiet, they pan with the board and scale with the zoom (b2-empty-board.png, n8-grid.png; `BoardCanvas.svelte` 944-953).
- **Icon buttons are named.** Every icon-only control has `aria-label` and `title` (`App.svelte` 294-299, `Menu.svelte` 62-75, `BoardView.svelte` 720-733).
- **Fixed controls.** The picker rows show Plus, Check, and X on every row with no hover (b3-one-card.png). The relation list's action row stays in one place (b0-entry.png).
- **Settings pictures and section marker.** Each appearance choice shows a small picture, and the Settings sidebar marks the section in view (9-settings.png; `SettingsSidebar.svelte` 11-26).

## Failing

Ranked by harm to the look or to legibility. Each "Decision" lists the options and marks one as recommended.

### 1. Names are cut off beside empty space

- **Problem:** The entry title, the board name, and the board counts truncate while the header row has free space or space held for controls that are absent.
- **Where:** 4-read.png shows "Stone Block 212..." with about 170 pixels empty between Edit and More. b2-empty-board.png and b10-renamed.png show "Overvi...". n1-note.png (current build) shows "1 card,...". Entry cause: one `nowrap` row (`EntryView.svelte` 448-521, style 675-684) holds the title, Read and Edit, a save slot with `min-width: 11em` that is empty in Read mode (693-699), Images (added after the screenshot, so it is worse now), and More. Board cause: one `nowrap` row (`BoardView.svelte` 696-786, style 891-917) holds the name, the counts, two text toggles, Fit, the zoom, New note, and More; the name keeps at least 4em and the count gives way first, so long names still truncate in the current code.
- **Fix:** Entry: put the title on its own full-width line, up to two lines (`-webkit-line-clamp: 2`), size per decision 3. Second line: tags on the left; Read and Edit, the save slot, Images, and More on the right. More keeps one position in both modes. This is the structure of Wikipedia's Vector 2022: title, rule, then a tab row. Board: move Mentions, Other guides, and the four backgrounds into one "View" menu button (Lucide `Layers`; checkable items for the layers, radio items for the background). Move Fit and the zoom readout into a fixed cluster at the bottom right of the canvas (Missing 3). The header keeps the name (flex 1), the count in `--text-sm` muted, New note, View, and More. That frees about 250 pixels at a 1216-pixel window.
- **Effort:** M.
- **Decision 1:** (a) title line plus toolbar line on the entry page, View menu plus canvas zoom cluster on the board (recommended); (b) keep one row and drop the 11em reservation in Read mode, accepting that More moves about 160 pixels when Edit starts; (c) keep one row and let the title wrap to two lines.

### 2. Edge labels rotate with the line and are clipped

- **Problem:** Relation labels follow the edge's angle, so short or steep edges show vertical or diagonal text that runs into the cards.
- **Where:** b4-all-cards.png and b5-no-mentions.png ("DROPS" vertical, "ned with Picka" cut). b6-nudged.png and b9-fit.png (diagonal). `BoardCanvas.svelte` 717-737 (`rotate({line.angle} ...)`), sizes 1023-1032 (11 and 10 pixels).
- **Fix:** Draw labels horizontal at the midpoint inside a pill: background `--bg`, 1-pixel `--border`, radius 3 pixels, padding 1 by 5 pixels. Verb 12 pixels, weight 600, letter spacing 0.03em. Qualifiers 11 pixels, `--muted`, on a second line in the same pill. Hide the qualifier line when the visible segment is shorter than the pill plus 16 pixels. HTML (HyperText Markup Language) labels in the world layer make the pill simple; the cards are already HTML. Lucidchart, Miro, tldraw, and Obsidian Canvas all keep labels horizontal.
- **Effort:** M.
- **Decision 2:** This reopens design section 6 ("the verb along it") because the screenshots show it unreadable. (a) horizontal pill at the midpoint (recommended); (b) along the line only within 30 degrees of horizontal, horizontal otherwise.

### 3. Links are underlined everywhere

- **Problem:** Every link draws an accent underline, so tables, panels, breadcrumbs, the top bar, and the sidebar footer look like an old web page, and the blue competes with the page title.
- **Where:** 1-guide.png (a column of underlined titles), b11-list-again.png, b0-entry.png (relation lines), and every screenshot (breadcrumbs, "Settings", footer). `app.css` 139-141 sets the color and leaves the browser's underline. Body wikilinks add a solid accent border (`app.css` 687-690; 4-read.png).
- **Fix:** `a { text-decoration: none; }` and `a:hover, a:focus-visible { text-decoration: underline; text-underline-offset: 2px; }`. Titles in tables in `--fg`, weight 500, with a row hover of `--chip-bg`. Breadcrumbs in `--muted`, the current one in `--fg` at 600. Body wikilinks in `--accent` with no border, underlined on hover and focus. Unresolved links keep the dashed muted underline (decided). Wikipedia's Vector 2022 draws links this way.
- **Effort:** S. **Decision:** none.

### 4. Body headings outrank the entry title, and the title block is cramped

- **Problem:** A body `#` heading (Georgia, 27.2 pixels) is larger than the entry title (system font, bold, 25.6 pixels), and the first heading sits about 10 pixels under the tag chips.
- **Where:** 4-read.png. `app.css` 6 (`--h1: 1.6rem`) and 444-446 (`.preview h1 { font-size: 1.7rem; }`). `EntryView.svelte` 675-687 (8-pixel and 6-pixel gaps).
- **Fix:** Body scale: h1 1.625rem serif 400 with its rule; h2 1.375rem serif 400 with its rule; h3 1.125rem sans 600; h4 to h6 1rem sans 600. Title block: a 1-pixel `--border` rule under the title line, as Wikipedia draws, and `--space-5` (24 pixels) between the toolbar line and the body.
- **Effort:** S.
- **Decision 3:** Entry title face. (a) `--font-serif` at 2rem, weight 400, like Wikipedia's article title (recommended; app pages keep sans titles, which separates content from chrome); (b) sans at 1.75rem, weight 600.

### 5. Selected and pressed states are hard to see

- **Problem:** Selection and "on" use `--chip-bg` (#e9e9e9) on `--surface` (#f4f4f4) or on white, a contrast of 1.1:1 to 1.2:1, so the current mode, the active view, and the layer toggles are barely visible.
- **Where:** 3-edit.png (Edit is "on" only by a slightly darker fill and bold). b2-empty-board.png ("Mentions" on, "Other guides" off). n4-tying.png ("Tie a string" pressed). `app.css` 344-347; `BoardView.svelte` 922-925; `BoardPanel.svelte` 420-423; `GuidesView.svelte` 88-108, where bold has no effect on an icon.
- **Fix:** Add `--accent-soft: light-dark(#e8f0fe, #1f2d45)`. Pressed toggles: `--accent-soft` fill, `--accent` text and icon, 1-pixel `--accent` border. Segmented control: a track of `--chip-bg` with 2 pixels of inset; the chosen segment on `--bg` with a 1-pixel `--border`, shadow `0 1px 2px rgb(0 0 0 / .12)`, weight 600. Selected list rows: `--accent-soft`. Hover stays `--chip-bg`. Accent on `--accent-soft` measures 5.6:1 light and 6.6:1 dark.
- **Effort:** S. **Decision:** none.

### 6. Edit mode shows CodeMirror's default look

- **Problem:** Headings and links are underlined, the gutter is a gray strip with line numbers, and the editor box stops well above the bottom of the window.
- **Where:** 3-edit.png and 3b-paste.png. `Editor.svelte` 35-41 (`lineNumbers()`, `defaultHighlightStyle`). `EntryView.svelte` 700-706 (`min-height: 60vh`). `app.css` 698-708.
- **Fix:** Our own `HighlightStyle`: heading lines at weight 600 and 1.25em, 1.15em, 1.05em, no underline; markup characters (`#`, `*`, `>`, `[[`, `]]`, `||`) in `--muted`; link text in `--accent`, no underline; inline code on `--surface`; quote lines in `--muted`. An `EditorView.theme`: `--font-mono` at 0.9375em, line height 1.6, padding 12 by 16 pixels, gutter background transparent with no border, line numbers in `--muted` at 0.8em, active line `color-mix(in srgb, var(--accent) 5%, transparent)`. The split fills the column height through a flex column instead of `60vh`. Long media names shown short with a replace decoration (`media/6a74…ad0.webp`), as Obsidian shows embeds; the stored text does not change.
- **Effort:** M.
- **Decision 4:** Line numbers. (a) off by default, with a setting under Appearance (recommended; review section 3.4 proposed it); (b) keep them on.

### 7. Task lists draw a bullet and a native check box

- **Problem:** Each task shows a disc and a system check box, which looks unfinished in notes and entry bodies.
- **Where:** n1-note.png, n2-checked.png, n3-green.png. `app.css` has no task rule; notes only pad lists (`BoardCanvas.svelte` 1196-1203). The checked boxes use the Windows blue, not `--accent`; the stylesheet has no `accent-color`.
- **Fix:** `.preview li:has(> input[type="checkbox"]), .preview li:has(> p > input[type="checkbox"]) { list-style: none; }` and `.preview ul:has(> li > input[type="checkbox"]) { padding-left: 0.2em; }`. Draw the box: `appearance: none; width: 1em; height: 1em; margin: 0 0.45em 0 0; vertical-align: -0.15em; border: 1.5px solid var(--field-border); border-radius: 3px;`. Checked: `--accent` fill with a white check through a mask image. Disabled boxes in entry bodies keep full opacity. Add `:root { accent-color: var(--accent); }` for the remaining native check boxes, radios, and the zoom slider.
- **Effort:** S. **Decision:** none.

### 8. Rendered markdown blocks are under-styled

- **Problem:** Paragraphs sit 8 pixels apart (4 in compact), tables have no header fill or cell borders, code blocks have 8 pixels of padding, nested quotes stack quote marks, and footnotes start without a separator.
- **Where:** `app.css` 135-137 (global `p`), 403-414 and 683-685 (tables), 487-504 (code), 507-531 (quotes), 667-681 (footnotes). The tight paragraphs show in 3-edit.png.
- **Fix:** Block spacing `margin: 0 0 0.85em` for `p`, `ul`, `ol`, `pre`, `table`, and `blockquote` inside `.preview`. Tables in Wikipedia's "wikitable" form: 1-pixel `--border` on every cell, `th` on `--surface` at 600, padding 0.4em 0.75em, `font-variant-numeric: tabular-nums`. `pre`: padding 12 by 16 pixels, line height 1.45, `--font-mono` at 0.875em, radius 6. Inline `code`: `--font-mono`, padding 0.1em 0.35em. Quote mark on the outermost quote only (`.preview blockquote blockquote::before { content: none; }`). First footnote: `margin-top: 2em; padding-top: 0.75em; border-top: 1px solid var(--border);`. Footnote numbers in brackets, as Wikipedia shows them.
- **Effort:** S. **Decision:** none.

### 9. A selected string turns into a thick purple bar

- **Problem:** Selection draws an 8-pixel accent band under a 4-pixel twine, and focus tints the 14-pixel hit path, so the string's own color disappears.
- **Where:** n5-string.png (red inside a blue band reads purple), n6-labeled.png (blue on blue), img-2.png. `BoardCanvas.svelte` 1060-1076.
- **Fix:** Keep the twine in its color at 3 pixels. Selected or focused: a 7-pixel `--bg` path under the twine, and an 8-pixel accent dot with a 2-pixel `--bg` ring at each end, as Miro marks a selected connector. Remove the stroke on `.hit` for focus. String label in the pill from item 2, with a 2-pixel left border in the string's color.
- **Effort:** S. **Decision:** none.

### 10. The top bar does not line up with the columns and mixes control styles

- **Problem:** Breadcrumbs start above the sidebar, "Settings" is an underlined link while "Search" is a button, chrome icons are accent blue, and the gray bar stacks under the white Windows title bar.
- **Where:** Every screenshot; the first crumb sits at x 92 while the content starts at x 292. 9-settings.png shows "Settings" twice. `App.svelte` 292-319 and 370-415.
- **Fix:** Lay the top bar on the grid of `.columns` (sidebar width, then content), so the first crumb starts at the content's left padding, as review section 2.1 proposed. Search: a field-shaped button, 240 pixels, `--bg` fill, 1-pixel `--border`, radius 6, magnifier icon, muted "Search", and the `Ctrl+K` key cap at its right end. Settings: an icon-only button (Lucide `Settings`, title "Settings (Ctrl+,)") with the pressed style on the Settings page. Chrome icons in `--muted`, `--fg` on hover; accent stays for primary actions, links, and selection. Top bar background `--bg` with its bottom border, so it merges with the native title bar.
- **Effort:** S to M. **Decision:** none.

### 11. The sidebar shows two selected rows, and the focus ring boxes part of a row

- **Problem:** The current page and the list's tag scope share one style, and the keyboard ring outlines only the name, not the row.
- **Where:** 8-trash.png ("Natural" and "Trash" both have the bar and the fill). 7-sidebar.png and 5-oak.png (a ring from the name's left edge to the count, inside a full-width highlighted row). `app.css` 360-378; `TreeRow.svelte` 44-68.

Ring on the row: `.tree-line:has(.tree-name:focus-visible) { outline: 2px solid var(--accent); outline-offset: -2px; }` and no outline on `.tree-name`. Use the same inset bar in the Tag editor tree, where `border-left` with `border-radius` bends the bar (`TagsView.svelte` 494-497).
- **Effort:** S. **Decision:** none.

### 12. Settings switch cards show no on or off state

- **Problem:** "Keep the right panel open while editing" and "Always hide the table of contents" are switches drawn as plain cards; the off state shows nothing and the on state looks like a radio choice.
- **Where:** 9-settings.png. `PrefCard.svelte` 18-30 and 45-48.

Radio cards (Density) become two tiles side by side, 220 pixels wide, picture on top (full width, 96 pixels tall), a 16-pixel radio circle at the top right, chosen tile with a 2-pixel `--accent` border. Descriptions say what the switch does ("The panel stays open in Split."), not what off means.
- **Effort:** S. **Decision:** none.

### 13. A notice moves the whole page and looks like a toolbar

- **Problem:** A notice pushes every column down by 49 pixels, so the board's cards jump under the pointer, and an info notice uses the top bar's gray with no icon.

### 14. Relation edges use the twine color and fade on cork

- **Problem:** Edges are brown `--twine` (#8a6d3b), which blurs them with strings, and edges and strings both lose contrast on cork.
- **Where:** b4-all-cards.png (brown edge) and n7-cork.png. `BoardCanvas.svelte` 938 and 994-1007. Measured: the brown edge on cork is 2.1:1; red, blue, and green strings on cork are 2.2:1 to 2.4:1.
- **Fix:** `--edge: light-dark(#4d5156, #b0b4ba)` for relation lines and arrowheads at 1.75 pixels (8.0:1 on white, 3.4:1 on cork). Strings at 3 pixels with a shadow path offset 1.5 pixels down in `rgb(0 0 0 / .22)`, which lifts them off every background as a real string does. Mention lines stay dashed `--muted`.
- **Effort:** S. **Decision:** none.

### 15. Page headers and panels follow no single pattern

- **Problem:** Each page builds its own header with its own gap below it, the right panel uses three heading styles, and the primary create action is an icon on some pages and text on others.
- **Where:** Header gaps of 4 pixels (`TrashView.svelte` 185-187, `GuideView.svelte` 385-387), 8 (`BoardsView.svelte` 155-157), 12 (`TagsView.svelte` 471-473), and 16 (`GuidesView.svelte` 177-179). b1-boards-list.png ("+ New board" with text) against 1-guide.png and 6-tags.png (a "+" icon). 5-oak.png: "ADD RELATION" in small caps, "DROPS" in bold, "Mentioned by (1)" in bold at 16 pixels (`RelationBuilder.svelte` 490-497, `RelationList.svelte` 293-297, `EntryPanel.svelte` 319-329). b3-one-card.png: the board panel spends a 40-pixel row on the fold icon alone (`BoardPanel.svelte` 207-212); 9-settings.png shows the same in the Settings sidebar.
- **Fix:** A `PageHeader` component: 48 pixels minimum, the title (`--text-xl` sans 600, or the entry title per decision 3), an optional muted subtitle, the toolbar at the right with 8-pixel gaps, then 16 pixels to the content. The primary create action is always the "+" icon button, New board included, per the owner's icon rule. Panels: one section title style (the overline in "System") for Add relation, Selected card, Add entries, Mentioned by, and Unresolved links; verb group titles stay as they are. Put each fold button in the first title row of its column.
- **Effort:** M. **Decision:** none.

### 16. Empty states are bare sentences, and an empty list keeps a disabled action row

### 17. Buttons vanish on gray panels, and fields have faint borders

- **Problem:** Default buttons are `--surface` gray, the same as the panels, and field borders (#d8d8d8 on white, 1.4:1) are under the 3:1 that WCAG 1.4.11 asks for control edges.

Fields and check boxes: 1-pixel `--field-border` (`light-dark(#888c91, #737373)`; 3.4:1 on white, 3.1:1 on `--surface`, 3.5:1 dark). Dividers keep `--border`. Native selects stay native.

### 18. Board cards look like form fields, and the two kinds of photo differ

- **Problem:** Plain cards are 180 by 56 cream boxes with 13-pixel text, and an entry card with an image (cream frame, border, 36-pixel caption band, dark in the dark scheme) differs from a board image (white frame, no border, 28-pixel band, white in both schemes).

- **Decision 7:** Plain cards. (a) an index card: `--paper` fill and one 1-pixel rule in `--string-red` at 40 percent opacity under the title (recommended; it fits the cork board); (b) a plain card with only the type changes.

### 22. The Warning alert title fails contrast, and alerts have no icons

- **Problem:** The Warning title uses `--tag-orange` (#e8710a) on white at 3.1:1 for 14-pixel text, and the five alert kinds differ only by color.

### Component rules

- **Selection.** Hover: `--chip-bg`. Selected row: `--accent-soft`, plus a 3-pixel inset accent bar in navigation trees. Keyboard focus: a 2-pixel `--accent` ring on the whole row or object. Selected board object: a 2-pixel accent outline, offset 2.
- **Toggle.** Pressed: `--accent-soft` fill, `--accent` text and icon, 1-pixel `--accent` border.
- **Segmented control.** `--chip-bg` track; the chosen segment on `--bg` with e1 and weight 600.
- **Buttons.** Default: `--bg` fill, `--control-border`. Primary: `--accent` fill, `--bg` text. Danger: `--danger` text; a solid `--danger` fill only for the confirm button in `ConfirmDialog.svelte` (line 27 is red text today). Link: no border. Icon: square at `--control-h` with an `--icon-md` icon.
- **Chips.** Tag: pill on `--chip-bg` with its color dot. Status: pill, dashed `--field-border`, `--muted`. Relation stage: `--radius-sm`, 1-pixel border.
- **Dashed means provisional or indirect.** Stub, unresolved link, Add tag, drop zones, mention lines, cards from other guides.
- **Links.** `--accent`, no underline, underline on hover and focus.
- **Page header.** `--header-h`, title, optional muted subtitle, toolbar at the right, then `--space-4`.
- **Panels.** A head row at `--header-h` with tabs or a section title and the fold icon; sections divided by a 1-pixel `--border`; section titles in the overline style.
- **Empty state.** Icon, one sentence, one muted line, the action; centered in its region.
- **Menus.** Rows at `--row-h`, a 16-pixel icon at the left, the shortcut right-aligned in `--muted`, the destructive item last after a separator.

## Do not do

- **Custom window title bar.** Hiding the native decorations loses Windows snap layouts, the system menu, and accessibility, to gain 32 pixels. Merge the colors instead (item 10).
- **Motion.** No transitions on selection, panels, the palette, the viewer, or zoom (design section 5).
- **Hover previews of links.** Wikipedia's page previews appear on hover; that is hover-only content and a moving surface, both decided against.
- **Colored tag fills.** Nine tinted chip colors make lists noisy; the dots carry the color.
- **Tilted cards and notes.** Random rotation breaks alignment, complicates edge clipping, and lowers legibility.
- **Photo textures from image files.** They add weight, show seams, and do not follow dark mode; procedural noise is enough (item 24).
- **Glass and blur.** Backdrop blur costs frame time on a large canvas and lowers text contrast.
- **Icon-only layer toggles.** "Mentions" and "Other guides" are states that need words; the labeled View menu keeps them clear.
- **Custom widgets for every native control.** Draw only the markdown check boxes and the switches; native selects and inputs keep platform accessibility.
- **Overlay scrollbars that appear on hover.** They hide where a list ends; the stable gutter (`App.svelte` 449) is right.
- **Handwriting fonts in notes.** Lower legibility, another bundled font, poor small sizes.
- **Narrowing the body width without the owner.** The owner widened it to 96ch on purpose (commit 2e5b721); offer Missing 7 instead.
- **Switching the accent to the icon's green.** Blue reads as a link in a wiki; adjust the icon, not the links.
- **Auto-dismissing notices.** Decided against (review section 4.6).
